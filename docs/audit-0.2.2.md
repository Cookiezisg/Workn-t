# 0.2.2 之前的大检查

0.2.1 发布后做的一轮检查。目的不是证明没有 bug（没有哪种检查能证明），而是把每一类 bug 交给能抓住它的方法，并且把没覆盖到的地方写明。

## 怎么查的

| 方法 | 做了什么 | 查出 |
| --- | --- | --- |
| 随机乱序测试（整个 mod） | 每轮 60 步，随机地开回合、结束、按按钮、敲命令、关标签页、藏面板、别的会话抢视频、页面变成登录页；每步之后检查几条永远该成立的事。修之前跑了 340 轮，修之后 450 轮（其中 150 轮让对外调用随机失败） | 2 处 |
| 随机乱序测试（页面脚本） | 同样的做法，每轮 150 到 220 步。修之前 800 轮，修之后 800 轮 | 1 处 |
| 变异检查 | 故意把页面脚本改坏 13 处，一次一处，看有没有测试失败 | 第一遍 3 处没被随机测试抓住，其中 1 处没有任何测试抓住；补强后每处都有测试抓住，剩 1 处是改了也没有可见后果的 |
| 独立审查 ×4 | 四个互不通气、也不知道作者想法的审查者，分别读引擎与多会话、页面脚本、守卫与钩子、测试与规则书的对照。每条发现要求给出具体的出错步骤 | 约 60 条，核实后属实并修掉的 40 多条 |

随机测试在日常套件里留了 26 轮；另有约 40 个具名测试，每个对应这次修掉的一处。测试总数从 126 到 182。

## 修掉了什么

按“你会不会直接撞上”排。

**会直接撞上的**

- 点过一次 `回到推荐` 之后，页面上的下一次按键（比如卡片上的 `回去看看`、`你别管我了`、菜单里的选择）没有反应。原因：页面重新加载后按键从 1 开始重新编号，而 mod 以为 1 号已经处理过了。
- Claude 正在干活时输入 `/worknt go`，要等回合结束才执行。
- 声音设成静音，第一条之后的视频可能有声：网站给新视频设置音量的动作，被当成了“你自己调了音量”。
- 你暂停的视频，在网站启动旁边那条时被重新放起来；划到下一条之后，新的一条又可能一直不动。
- 开着网站自己的连播时，`再看一条` 会一条接一条放到 5 分钟上限；划到一条时长还没读出来的视频，卡片会立刻回来。
- 离开超过 5 分钟再回来，立刻被问 `还在吗？`。
- 不在推荐流上时（个人页、直播间、认不出的页面），回合跑完、有会话等你，都没有任何提示；状态带上也没有 `回去看看`。
- 第一次点邀请后回合就结束了，那三个问题会一直留在状态带上，而且没有“算了”。
- `/worknt reset` 之后，下一次计数会把重置前的账单带回来。

**标签页和多会话**

- 视频页还在加载时被别的会话接走，这边不放手，加载完还会把视频亮出来。
- 新标签页开不出来时，会往你自己的标签页里导航，把它当成视频页，十分钟后还会把它关掉。
- 从没亮出来过的、被接走的、操作不了的标签页，会一直留着；到了十分钟面板恰好问不到时，留着的标签页被忘掉而不是被关掉。
- mod 在回合中途重载后，以为没人在干活：视频暂停，回合结束时不叫你。
- 一问即答的提问会让会话一直停在“等你”；权限请求会被同名工具的任何一次调用结束掉。
- `还在吗？` 没人理时，用 `/worknt go` 开始的摸鱼永远不结束，其他会话一直看到“视频开在…”。

**守卫**

- 一个批量调用里“先跳到一个会转向抖音的地址，再读取页面”，守卫只在事前看了一眼，全部放行，模型能读到你登录状态下的页面。现在每一步执行完再看一次，落在片源站点上的结果一律不给。
- 地址写成浏览器照样能读、守卫却认不出的样子（百分号转义、全角字母、句号代替点）。
- 工具报错时、或者返回的不是文字列表时，标签页标题和地址没有被抹掉。
- mod 在这个会话里休眠时，守卫是关着的。
- 没指定标签页、而前台是你的视频时，拒绝的话是“请告诉用户先运行 /worknt off”。现在是“请新开你自己的标签页”，Claude 可以在后台接着干，不用你关任何东西。

**其余**

- 自查输出里的页面地址会带出账号名和搜索词。
- 中文句子里和 TikTok 之间没有空格。
- 会话被清空后状态带还留着“摸鱼中”。
- 若干计数上的小漏：会话结束前最后几秒的 Claude 工时没记进账单。

## 查出来但没改的

| 事 | 为什么 |
| --- | --- |
| 能运行命令的模型可以直接改 Workn't 的设置文件，把守卫关掉 | 这是 mod 的位置决定的：它管得了浏览器调用，管不了命令行。已在规则书（P-11）和说明文档里写明守卫不是安全边界 |
| 一个闲着的会话，状态带上的那一行和打开的设置面板不会跟着别的会话的改动刷新，要等它自己下一次有事 | 让每个闲着的会话都定时醒来代价不值；摸鱼中的和干活中的会话不受影响 |
| “你发起的回合”的判断：如果你输入了一条不会开始回合的东西，紧接着后台任务唤醒了会话，那个回合会被当成你发起的 | 取决于引擎在什么情况下报告“你提交了输入”，没法在测试里确认；后果只是多出现一次邀请 |
| 只处理视频，不处理单独的音频（图文帖子的配乐） | 没有在真页面上见过，先不猜 |
| 集成测试里视频页是个替身，真正的页面脚本只在它自己的测试里运行；两个会话的协调，测试里另一个会话是手写的状态文件，不是第二个真的 mod | 这是测试结构上最大的缺口。页面脚本和 mod 之间的约定（按键编号、心跳）这次出的 bug 就藏在这条缝里。靠 `docs/walkthrough.md` 的真桌面走查来补 |

## 规则书里还没有测试盯着的

以下规则有代码、但没有测试直接检查它，或者测试检查得不够：

- S-8 交键盘焦点：只检查了“点过一下”，没有检查点的是哪儿。
- W-2 页面出帧的计数：测试里是手动设的“没在出帧”，计数本身没跑过。
- C-2 的权限确认和确认计划：接线这次重写了，测试里没有真的触发过这两个事件。
- C-6 后台子任务的回合不算主回合：没有测试。
- R-7 宿主崩溃后的接管、R-2 两个会话同一毫秒认领：只有单元测试。
- R-10 询问频率、D-2 日志行数上限：没有测试。
- T-2 里 `idle`、`lang` 等命令和设置文件的读入校验：没有测试。

这些，连同所有“只有测试、没在真环境里跑过”的，都在 `docs/walkthrough.md` 里有对应的步骤。
